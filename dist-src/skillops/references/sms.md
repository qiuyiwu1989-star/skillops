# SMS · Skill Management Standard v2.0

> **AI 技能的质量评级标准**。100 分制 = 4 支柱 × 10 维 × 每维 0-10 分。
> 本标准**公开发表**，欢迎第三方实现、引用与批评。署名：造物云 · 邱懿武。
> 设计原则：**评分是钩子，不是主张**——分数的价值在于指出"怎么变好"，不在于排名。

## 为什么需要它

技能（SKILL.md / 提示词 / 工作流）正在成为个人与组织的资产，但"什么算好技能"没有共识：能跑 ≠ 好用，好用 ≠ 能进入更大的 agent 系统，能进系统 ≠ 敢在生产里用。SMS 把这四层拆成四个支柱，各自可打分、可对照、可提升。

## 四支柱 × 十维

### 支柱一 · 可理解 COMPREHENSION
> 灵魂拷问：**人和 agent 能不能搞懂它、知道何时用？**

| 维度 | 判据 |
|---|---|
| **清晰度** CLARITY | 用途、边界、价值是否一眼可懂；面向中文用户时，中文表达是否清晰自然（本土适配） |
| **可调用性** INVOCABILITY | 触发设计是否让 agent 在对的时机准确召唤、不漏召/误触。**自检：删掉正文只留 description，agent 还能不能判断何时该调用？** |

### 支柱二 · 可执行 EXECUTION
> 灵魂拷问：**它能不能真把活干好、且稳定？**

| 维度 | 判据 |
|---|---|
| **可执行性** EXECUTABILITY | 步骤是否具体到可照做，含判断标准与异常处理，无"凭感觉"的空步 |
| **输出稳定性** STABILITY | 不同输入 / 不同人调用，产出结构是否一致、可预测 |
| **结果质量** QUALITY | 产出是否达资深从业者水准，**沉淀了隐性经验/坑(gotchas)与判断**，而非复述常识或套模板 |

### 支柱三 · 可工程 ENGINEERING
> 灵魂拷问：**它能不能进入更大的 agent 系统？**

| 维度 | 判据 |
|---|---|
| **可复用性** REUSABILITY | 能否抽象迁移到多个场景 / 行业，而非绑死单一任务 |
| **可组合性** COMPOSABILITY | 输入输出契约是否清晰，可作为更大工作流的一个节点被编排 |
| **可评估性** EVALUABILITY | 是否有明确成功标准，输出好坏可被测试 / 回归 / 客观判断 |

### 支柱四 · 可信赖与价值 TRUST & VALUE
> 灵魂拷问：**敢不敢用、值不值得？**

| 维度 | 判据 |
|---|---|
| **安全性** SAFETY | 越界 / 注入 / 敏感信息 / 合规风险是否被主动处理；企业可否放心接入 |
| **商业价值** BUSINESS VALUE | 是否解决高频、真实、有支付意愿的问题，价值可被量化 |

## 打分锚点（每维 0-10）

把"凭感觉打分"变成"对号入座"：

| 分 | 含义 |
|---|---|
| **0** | 缺失 |
| **2** | 雏形——有意识但几乎不可用 |
| **4** | 基础——能用但明显不足 |
| **6** | 合格——达到可公开门槛 |
| **8** | 良好——稳定可靠，少数瑕疵 |
| **10** | 卓越——标杆级，可作范例 |

## 段位（总分 100）

对外**更强调段位而非具体分数**——段位才是可决策的信号。

| 段位 | 分数 | 含义 |
|---|---|---|
| **S** | 86–100 | 核心资产 · 旗舰级，可主推、可商业化 |
| **A** | 76–85 | 稳定可用 · 可对外公开、可放心调用 |
| **B** | 64–75 | 公开门槛 · 达到发布线，仍在打磨 |
| **C** | 50–63 | 概念 · 雏形阶段，建议继续完善 |
| **D** | <50 | 待重写 · 信息不足或未成熟 |

## 三条最锋利的判据

多数技能栽在这三条上，评分与提分时优先看：

1. **可调用性自检** —— 删掉正文只留触发描述，agent 还能不能知道何时调用？（description 是路由规则，不是简介）
2. **结果质量的隐性知识密度** —— 奖励"老师傅经验/边界/反例/坑"，惩罚复述常识与套模板。这是好技能与模板的分水岭。
3. **可评估性** —— 说不出"怎么算做对了"的技能，无法迭代，也无法被信任。

## 怎么用

- **静态分 = 潜力，实证数据（调用量/成功率）= 实绩。** 两者并列讲，不混为一谈。
- 评分后接**提分**（见 [playbooks.md](playbooks.md) 的 skill-coach）：定位最弱 3 维 → 对症修改 → 复评看跨档。
- 发布门槛建议设在 **B 段（64）**。真实数据参考：一次全库审计中，52 个技能均分 56.4；设了发布门槛后的公开目录 25 个，均分 70.4——**门槛把均分抬高 14 分，这就是"管理"在做的事。**

## 诚实声明

SMS 是一套**主观标准的结构化**，不是客观真理。它的价值在于：把模糊的"这个技能好不好"拆成十个可讨论、可对照、可改进的维度。不同团队可以调整权重与门槛——**但请保留维度定义与锚点阶梯，这样分数才可比。**
