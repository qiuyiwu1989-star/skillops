# 技能 HRD 方法论

> 为什么要用人事管理的思路管 AI 技能。本文是这套体系的**理念底座**，`playbooks.md` 是它的执行体，`sms.md` 是它的度量衡。

## 一句话

**把每个 skill 当员工管。** 技能散在哪都行（file-as-truth），HRD 负责它们的全生命周期——招聘、落户、调度、考核、培训、绩效、退役。

## 判断的起点：今天的技能世界 = npm 之前的 JavaScript 世界

格式已经开放（SKILL.md 事实标准），版本已经免费（git），但缺三样东西：
- **没有花名册** —— 你有多少技能？散在几个目录？没人答得上来。
- **没有质量共识** —— 什么算好技能？凭感觉。
- **没有调度** —— 新项目要装哪些技能、装的是不是最新版？靠记忆。

缺的不是存储，是**中间层**：registry + 信任 + 调度。这正是 npm 之于 JavaScript、GitHub 之于 git 的位置。

## 为什么是 HRD，不是"文件夹"或"知识库"

知识管理（KM）失败了五十年，根因只有一个：**文档是死的，不会干活。** 写下的 SOP 没人读，读了也执行走样。

AI 第一次解开这个死结——**skill = 会干活的文档**。于是知识管理的问题变成了人力资源的问题：

| AI 改写的变量 | 过去 | 现在 |
|---|---|---|
| 知识的可执行性 | 文档是死的，know-how 只能人传人 | 技能会自己干活 |
| 能力获取成本 | 招一个人 3 个月，培养 3 年 | 装一个技能 3 秒 |
| 能力复制边际成本 | 顶级销售的方法论只能带 5 个徒弟 | 封成技能，全员即时调用，边际成本≈0 |
| 能力考核方式 | 一年一次、主观、考人 | 随时可跑、客观、考技能本身 |
| **能力折旧速度** | 技能十年不过时 | **模型三个月换代，技能会漂移、会退化** |

最后一行是"管理"变得必要的根源：**技能不是存起来就完事的资产，它会退化、会漂移、会过时。** 没有人事部的组织不是没有人才，是不知道自己有什么人才、谁在退步、谁该退休。

## 生命周期九动词

| HR 动作 | 技能动作 | 含义 |
|---|---|---|
| 招聘 | **捕获** | 技能出生（会话中写出）或从外部引入 |
| 报到 | **落户** | 登记身份 `id: namespace/name`（写进 frontmatter 一行） |
| 建档 | **入册** | 进入花名册（scan 盘点索引） |
| 派岗 | **调度** | 把技能装进对的 agent / 项目 |
| 考核 | **考核** | SMS 静态评级 + 实测通过率 |
| 培训 | **培训** | 定位弱维、重写提分 |
| 绩效 | **绩效** | 调用量、分数趋势、退化预警 |
| 入编 | **入编** | 组织收编个人技能：带血缘、锁版本、考核门槛、权限、审计 |
| 退休 | **退役** | 可逆归档，绝不删除 |

## 五层架构

| 层 | 内容 |
|---|---|
| **L0 格式** | SKILL.md 开放标准（不发明私有格式）+ `id`/`version` frontmatter |
| **L1 本体** | 卷（vault）+ 花名册 + 调度 —— **每日动词** |
| **L2 信任** | SMS 评级 + 实测 + 使用遥测 |
| **L3 流通** | registry：发布 / 订阅 / 安装 / 更新 |
| **L4 治理** | 组织控制平面：入编 / 锁版本 / 门槛 / 审计 |

本包覆盖 L0-L2；L3/L4 是平台能力。

## 六条设计铁律

1. **file-as-truth** —— 真身是用户自己的文件夹，索引永远只是缓存。任何"把技能复制进我的数据库"的设计都会制造第二份拷贝，**分裂即死亡**。
2. **不当运行时** —— 不做生产工作负载的运行时。技能永远跑在用户自己的 AI 里。评级是**质检台架**，不是替它上班（HR 面试候选人 ≠ 替他上班）。
3. **agent 操作，人拍板** —— 人事系统的操作者是 agent，人只读汇报、做决策。CEO 从不亲手操作 HR 系统；HR 专员操作、向 CEO 汇报。**把操作台发给 CEO 是产品设计错误。**
4. **用户使用，组织管理** —— 两级命名空间：个人（`alice/`）创作使用，组织（`acme/`）收编治理。个人技能被组织采用不是复制粘贴，是带血缘的**入编**。
5. **退役可逆，删除不可逆** —— 永远标记，不删除。
6. **开放格式与标准，闭合数据与网络** —— 格式跟随、rubric 公开；护城河在托管的信任数据与网络，不在藏起来的评分表。

## 对外一段话（可直接复用）

> 每个用 AI 的人都在积累技能（提示词、SKILL.md、工作流），但它们散落各处：没有花名册、没有版本、坏了没人知道、好坏没有标准。技能 HRD 用人事管理的思路管技能——落户、调度、考核、培训、绩效、退役，全生命周期。个人先把自己的技能管起来；组织像发工牌一样发技能包。不做运行时：技能永远跑在你自己的 AI 里，我们做的是那个人事部。

## 词汇表

**卷**（技能根目录）· **花名册**（索引）· **落户**（登记 id）· **入册**（进花名册）· **分身**（同内容多处拷贝 = 手工部署）· **分歧**（同身份不同内容 = 版本漂移，最要命）· **入编 / 续聘 / 退役**（组织治理动词）· **段位**（S/A/B/C/D）。
