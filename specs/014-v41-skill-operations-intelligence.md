# 014: V4.1 技能运营智能

## 要什么

把 SkillOps 从“技能可信供给与组织治理”升级为“技能运营智能”：每个已发布 Skill Release 都拥有可路由、可组合、可度量、可改进的运营档案。系统只生成判断、证据和计划，不执行第三方技能，不替人发布。

## A. Skill Record 2.0 与路由质量

- 定义稳定、版本化的 Skill Record，绑定 `skillId`、`releaseId`、`packageDigest`、来源、中文/原文元数据、任务意图、输入输出、依赖、权限、兼容环境和当前证据引用。
- 路由元数据必须回答“何时使用、何时不要使用、与谁容易混淆”。缺字段、未知字段、正文或秘密夹带均失败关闭。
- 提供确定性 Routing Assessment：覆盖元数据完整度、正反例、意图区分度、冲突说明和可迁移性；评分只能描述静态路由质量，不能伪装成运行成功率。
- Record 或路由字段变化必须形成新 digest，不能继承旧路由评估。

## B. 技能组合规划

- 用稳定 `skillId/releaseId` 构造有向依赖图，支持 required/optional/conflicts/before/after 关系。
- 输入任务意图与候选 Skill Records，输出确定性组合计划、顺序、选择理由、未选原因、冲突与阻断项。
- 明确 release 缺失、证据过期、权限不兼容、循环依赖、版本冲突时失败关闭。
- 计划只引用公开摘要，不包含 Candidate 身份、正文、路径、prompt/output/token，也不加载或执行技能。

## C. 运营指标与退化判断

- 定义隐私安全的 append-only 运营事件：曝光、被选择、被调用、成功、失败、人工接管、成本和时延。
- 事件必须绑定 organization/project/skill/release/package 与时间窗口；禁止正文、用户输入输出、密钥、身份原文和任意高基数字段。
- 聚合形成 `曝光 → 选择 → 调用 → 成功 → 复用` 漏斗，并输出成本、时延、失败类型、人工接管率和版本趋势。
- 区分“零使用”“高使用低效用”“证据不足”“显著退化”；低样本不得作强结论，指标不能自动触发发布、撤回或退役。

## D. 集成与产品体验

- 统一投影 Skill Record、Routing、Composition 和 Operations，供市场详情与中文运营页只读消费。
- 市场支持按任务意图解释“为什么推荐”，详情展示可组合技能、权限边界与路由证据。
- 运营页展示漏斗、退化队列、待 Coach 和待复评项目；所有治理动作仍走现有显式 CLI/台账协议。
- 形成至少 3 个完整 Release 的离线演示和跨模块 E2E。

## 不做什么

- 不连接真实模型、生产造物云、真实 IdP 或公网分析服务。
- 不执行第三方 Skill、scripts 或工具，不成为运行时或编排执行器。
- 不使用下载量、热度或单一总分替代安全、许可、Eval 和人审硬门。
- 不把原始 prompt/output、用户身份、密钥、本地路径写入运营台账。
- 不自动修改 Skill 真身，不自动发布、入编、撤回或退役。
- 不修改冻结的 `api-server/`、`xiaoneng/` 和线上站点。

## 验收清单

- [x] Skill Record 固定 schema、稳定 digest、版本绑定和严格隐私门禁通过单元测试。
- [x] Routing Assessment 能识别缺少正反例、意图混淆、冲突未声明和版本失效。
- [x] Composition 能稳定排序，并对循环、冲突、过期证据和权限不兼容失败关闭。
- [x] 运营账本 append-only、原子保存、重启一致，并拒绝敏感或高基数字段。
- [x] 漏斗、成本、时延、人工接管率、版本趋势和退化判断由事件重算，不信任调用者汇总。
- [x] 市场与运营视图为中文、响应式、无公网资源，只消费公共投影。
- [x] 3 个 Release 离线 E2E 覆盖推荐解释、组合计划、运行事件、退化与 Coach 建议。
- [x] 全仓测试、`node --check` 与 `git diff --check` 通过。

## 实现约束

- G3；先冻结 schema，再实现；每个工作包必须有独立黑盒测试。
- 零新增运行时依赖，核心使用 Node.js 内置模块。
- 时间、阈值和样本数据均可注入，测试不得联网或调用模型。
- Agent 只产生评估、组合和 Coach 提案；人类终审与现有可信门禁保持独立。
