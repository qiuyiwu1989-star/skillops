# V4.7 市场商品与获取体验第二阶段

## 状态

completed in local preview

## 目标

把第一阶段统一后的市场页面接到已经完成的 V4.5 商业授权内核，让企业用户在一个页面理解并验证四类状态：

`已授权 → 可免费获取 → 需采购 → 暂不可用`

免费获取必须真实生成 Order 与 Entitlement，随后可被企业授权库和技能管家消费。技能市场仍不执行技能，不自动采购，不连接真实支付或生产工作台。

## 产品体验

- 公开市场首页新增“企业获取入口”，展示稳定 Product、Release、能力类型、中文说明、价格模型、授权状态和下一动作。
- 已授权能力进入技能管家；免费能力必须由用户明确点击确认；付费/询价只展示采购动作；不可用能力展示阻断原因。
- 免费获取成功后，页面在当前会话中显示 Entitlement 摘要，并把能力状态更新为“企业已授权”。
- 页面继续保留可信技能目录、SMS、Eval、来源、许可、安全和详情深链，不把商业状态与质量证据混为一谈。

## 本地获取服务

- 仅由本地预览服务器在 `127.0.0.1` 暴露：
  - `GET /api/v1/preview/acquisitions`
  - `POST /api/v1/preview/acquisitions/free`
- 服务使用正式 `AcquisitionLedger`、`createFreeOrder` 和 `issueEntitlement` 路径，不直接拼接授权结果。
- 请求只接受固定 Product、Release、Offer Revision 和幂等键；组织由服务端固定能力提供，不接受调用者自报。
- 只允许当前 published、active、free Offer。付费、召回、未知 Product/Release/Offer 和未知字段全部失败关闭。
- 请求体上限 16 KiB；非 JSON、重复幂等冲突、符号链接和账本故障不得产生半提交。
- 响应只返回 Product/Release/Entitlement/权利/时间/摘要，不返回账本路径、Order 全文、身份、CAS、Prompt、Output、Token 或 Secret。
- 本地账本默认位于操作系统临时目录，可通过显式环境变量覆盖；不写入仓库，不代表生产授权。

## 验收

- [x] 首页可同时展示四类获取状态，中文原因和下一动作清晰。
- [x] 免费获取必须经过显式按钮，成功后状态变为已授权。
- [x] 同一幂等请求重放不重复签发 Entitlement；不同请求复用幂等键冲突。
- [x] 付费、不可用、错误 Product/Release/Offer 不能通过免费接口。
- [x] API 响应和页面不泄露本地路径、账本正文、身份或执行材料。
- [x] 市场既有筛选、可信货架、详情深链和移动布局不回归。
- [x] 390px 无横向溢出，键盘焦点和低动效有效。
- [x] 市场测试、语法检查、diff 检查和浏览器验收通过。

## 非目标

- 不接 Stripe、微信支付、支付宝、发票、退款、结算或真实采购系统。
- 不接真实生产数据库、生产 MarketRegistry、生产 IdP 或生产造物云 API。
- 不执行技能，不发送 WorkOrder，不上传业务材料，不调用模型。
- 不自动获取免费技能，不自动购买，不把浏览器状态当作可信服务端授权。
