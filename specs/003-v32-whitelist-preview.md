# 003: V3.2 白名单试运行与市场预览

## 要什么

把 V3.1 的可信供给核心推进成可操作的本地试运行版本：运营者用显式白名单清单采集 GitHub 仓库快照，形成候选与汇总报告；市场预览只读取 `approved listing`，展示来源、版本、许可、安全、SMS/Eval 与审核范围。

## 不做什么

- 不做 GitHub 全网爬虫、搜索排序和后台定时任务。
- 不自动批准或公开候选。
- 不调用冻结的 `api-server/`、`xiaoneng/` 或线上服务。
- 不批量运行付费 LLM，不伪造 SMS/Eval 分数。
- 不把本地预览当作生产市场前端。
- 不推送、合并或部署生产。

## 验收清单

- [ ] 白名单是显式 JSON，支持 GitHub URL、ref 和可选路径前缀。
- [ ] 每次采集解析远端 commit，将仓库快照固定到该 commit 后再扫描 `SKILL.md`。
- [ ] 网络失败、无技能、超限与非法来源进入报告，不污染既有候选。
- [ ] 同来源再次采集能刷新候选；内容或许可变化使批准失效。
- [ ] 采集命令输出候选数、状态、许可、安全和重复统计。
- [ ] 测试用本地 git fixture 验证完整流程，不依赖公网或密钥。
- [ ] 预览构建命令只导出 approved listing；无批准项时提供明确空状态。
- [ ] 预览支持搜索、分发类型筛选、详情证据查看和移动端布局。
- [ ] 页面不加载生产 API，不包含候选正文或未批准数据。
- [ ] 自动化测试、语法检查和浏览器桌面/移动验收通过。

## 实现约束

- 零运行时依赖，Node.js ESM 与原生 HTML/CSS/JS。
- 新代码仅写入 `trusted-supply/`、`market-preview/` 和相关测试/文档。
- 白名单采集使用只读 `git` 命令与临时目录，禁止执行仓库代码。
- 限制仓库数、单仓文件数和工件大小；拒绝符号链接与路径逃逸。
- 预览数据是构建产物，来源只能是 `CandidateStore.listListings()`。
