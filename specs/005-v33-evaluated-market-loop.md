# 005: V3.3 评估驱动的能力市场闭环

## 要什么

把现有可信候选与只读市场预览推进为可发现、可判断、可安装的本地市场版本。所有公开能力必须依次通过硬信任门、SMS v2.0 质量评估和人工批准；首页使用分类与可信货架帮助发现，详情页解释价值、评分证据和安装边界，安装继续复用现有 deploy 台账与漂移保护。

## 用户闭环

`任务搜索 → 分类/货架发现 → 卡片比较 → 详情证据 → 安装预览 → deploy → lock 台账`

## 评估体系

### 第一层：不可抵消的硬门

- 格式：有效 `SKILL.md`、名称、description 与正文。
- 来源：平台坐标、版本、签名/commit、内容指纹完整。
- 许可：允许分发，或明确降级为 `source_link_only`。
- 安全：阻断级问题直接隔离，不允许 SMS 或人工 waiver 绕过。

### 第二层：SMS v2.0 静态质量

- 四支柱：可理解、可执行、可工程、可信赖与价值。
- 十维：清晰度、可调用性、可执行性、输出稳定性、结果质量、可复用性、可组合性、可评估性、安全性、商业价值。
- 每维 0–10，总分 100；必须保存逐维分数、理由和证据。
- 评分绑定内容指纹与 `rubricVersion=SMS-2.0`；内容变化后评分失效。
- B 段（64）是公开质量门槛；A 段（76）才可进入精选候选；S 段（86）才可标记旗舰候选。
- SkillHub TRACE、下载量、收藏量不得替代或混入 SMS。

### 第三层：实证 Eval

- Eval 记录测试集、成功率、结果证据和运行环境。
- 静态 SMS 表示潜力，Eval 表示实绩；分别展示。
- V3.3 可保留 `eval=pending`，但不得伪造成功率或案例。

## 并行工作包

### A · SMS 评分管线

- 建立 SMS 10 维数据契约、严格校验、段位映射和内容指纹绑定。
- 增加 CLI 导入/查看评分；批准时拒绝过期或结构不完整的评分。
- 给当前最多 2 个 `review` 候选生成逐维评估草案，不自动批准。

### B · 外部格式兼容

- 安全支持常见 YAML 多行文本、列表和嵌套 frontmatter。
- 只提取格式审核所需标量；禁止 YAML tag、对象构造和代码执行。
- 重审当前 screening 候选，记录哪些仅因许可不清继续停留。

### C · 市场发现与详情

- 首屏任务式搜索、分类入口、可信货架和市场化技能卡。
- 独立详情体验展示场景、来源、SMS 十维、许可、安全、版本和安装边界。
- 不显示虚假下载榜、五星评分、收藏量或个性化推荐。
- 严格遵循 SkillOps Design System 与 Rams 默认主题。

### D · 集成与安装闭环

- 合并三条工作流，扩展 listing 市场元数据。
- 从详情页生成可验证的安装预览；复用 deploy 的 lock 与漂移保护。
- 浏览器完成桌面/移动、搜索、筛选、详情和安装边界验收。

## 不做什么

- 不自动批准、安装或执行第三方 Skill。
- 不批量调用付费 LLM；外部评分只能显式导入并记录 scorer。
- 不修改或部署冻结中的 `api-server/`、`xiaoneng/` 和线上站点。
- 不在许可不清时公开复制第三方正文。
- 不做支付、评论、作者认领和真实个性化推荐。

## 验收清单

- [ ] SMS 结果含 10 维分数、理由、证据、总分、段位、scorer、时间、rubric 版本和内容指纹。
- [ ] 缺维、越界、总分不一致或指纹过期的 SMS 不得通过质量门。
- [ ] 安全/许可硬门不能被高 SMS、TRACE、热度或 waiver 抵消。
- [ ] 常见安全 YAML frontmatter 可解析，危险 tag 与异常结构失败关闭。
- [ ] 当前 SkillHub 候选重新审计，并形成可解释的 review/screening 队列。
- [ ] 首页具有任务搜索、分类、至少 3 种可信货架和市场化卡片。
- [ ] 详情页展示 SMS 与 Eval 的区别、来源证据及真实安装入口。
- [ ] 安装不会覆盖未知目录或有漂移的目标，复用 lock 台账。
- [ ] 自动化测试全通过，桌面与移动浏览器无横向溢出、console 0 error。
- [ ] 本地完成至少 8 个真实候选、3 个完整 SMS、3 个 approved listing 的 Go/No-go 演示；不足则诚实报告 No-go。
