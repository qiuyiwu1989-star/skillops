## 产品与数据安排

- SkillOps 是一个产品，个人 AGI 是第一个私有工作区。公共目录收录显式公开的 Release。未来工作区与组织数据按所有权隔离，私有文档、案例、评估输入及终端回执保持原访问边界。
- 产品统一先于写入接管。迁移期间，个人中心原有正式版本仍是其资产权威，SkillOps 通过映射读取。完整包、版本历史和证据迁移比对通过后，逐条将写入权交给 SkillOps。网页、HTTP API、两种 MCP 入口读取同一个 Release，旧接口通过适配保持兼容。每条资产在任一时刻有一个写入方。
- Git 风格的体验保留草稿修订、差异、发布、回退。Git 仓库或本地文件可以是明确登记的编辑来源，导入与发布固定具体提交及包摘要。归档或回滚通过状态和当前发布指针实现，历史包内容不可原地替换。
- 一个技能有稳定 ID 和完整包。插件有独立 ID、版本、manifest、成员版本与摘要，也可声明客户端适配。方法资料是技能或改进的引用证据。SMS 记录绑定草稿修订或发布摘要、模型及时间。试岗记录也绑定具体内容、用例和依据。
- 批量对照以来源和完整包摘要为证据。只有正文时可标记正文匹配，但继续核对附件。同名异内容进候选，原有公开 slug、私有范围、来源 ID、版本记录和评估不覆盖。

## MCP 与安装

- 个人 AGI 沿用现有个人 MCP。其他用户通过 SkillOps 自己的 MCP 连接各自工作区。两个入口共用后端的身份、版本解析与授权规则。Web 管理和脚本继续使用 HTTP API。
- MCP 起步能力是搜索、获取指定版本和 manifest、提交反馈、在授权范围内请求诊断或候选。发布和替换终端版本由用户确认。跨账户访问、公开发布与普通读写分权，SaaS 代理按客户端授权并支持撤销。[MCP Authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)
- 从聊天里读取文本技能可以只用 MCP。安装包含文件、脚本或 hooks 的插件用完整包和本地 CLI/连接器。终端验证摘要、按客户端格式安装并报告回执。导入、阅读、评分均不自动运行包内脚本。

## 联合分工与线上接口

- SkillOps 会话负责国内控制台的已发布视图、统一界面，以及 MiMo SMS 评分与培训服务。个人技能中心会话负责正式发布、完整包与试岗证据、迁移去重、个人 MCP 和连接器验收。首轮只做读取与安装验证，个人中心继续管理正式发布。
- 线上已增加 3 条「已纳入个人中心」关联，个人中心已提供「复制给 Agent」。双方会话核对了 xuqiu-jianbao 1.0.0 的 SkillOps 列表、详情、个人中心版本记录和正式 MCP。2026-11-16 另从服务器核对，映射文件是 /var/lib/skillops-cn/personal-skill-links.json，现有响应契约为 personalCenter: { id, version, hash }。该字段用于导航和展示关联。
- 发布 SkillOps 前，先以 /opt/skillops-cn/api/platform.js 和 /opt/skillops-cn/web/dashboard/index.html 的线上现状对照本地改动，合并并保留已有的 personalCenter 列表和详情行为。关联未登记时，仍按 SkillOps 原有条目展示。
- 已发布视图需要按工作区授权读取发布记录。技能侧至少需要稳定技能 ID、发布 ID、具体版本、完整包摘要及其算法、正式版网页链接、文件清单和试岗摘要或深链。插件侧至少需要插件 ID、发布 ID、具体版本、包摘要、manifest、成员的固定版本或包内路径与摘要、连接器可用的取包方式。分别标明包的摘要、SKILL.md 摘要、ZIP 摘要和终端实际安装摘要的作用，只有相同口径才直接比较。
- 联合样板固定为「用户价值叙事」1.0.1 和 product-management 1.2.0。SkillOps 的网页字段与个人 MCP 对上同一发布记录，插件回执确认对应包。待确认服务间只读鉴权、字段命名和现有字段的摘要口径，再实现跨服务读取。

## 首轮与验收

1. 先打通「用户价值叙事 1.0.1 + product-management 1.2.0」。SkillOps 显示一份版本档案，个人后台保留深链。网页和个人 MCP 明确读取同一发布 ID、版本号、完整包摘要。原试岗记录完整，插件 manifest 能解析到锁定的成员。
2. 沿用已有 MiMo 评分与培训功能。基线与候选能并排对照，培训只生成候选。使用合成的第二工作区账号验收私有技能、附件、评估与 Agent 连接隔离。
3. 批量归并先生成只读清单。可直接关联、待补包、候选冲突逐项可追溯。通过一条完整包安装及终端回执后再扩大范围。发布与读端切换分步验证，保留旧记录作为回滚依据。

首轮范围聚焦现有两套系统的统一。市场交易、支付、自动发布和通用 Agent 运行时留待独立规划。
