# V4.10 技能供给与目录扩充管线

## 目标

把市场从少量手工演示卡升级为可重复运行的技能供给管线。首批同时保留两种真实状态：

- `approved`：已经通过现有 CandidateStore 审核边界的演示技能；
- `indexed`：从获准的本地技能卷发现并完成格式、来源路径、许可与静态安全检查，但尚未完成 SMS、Eval、完整包和双人终审。

## 首批范围

- 造物云与用户自有方法论技能；
- 项目自身 SkillOps；
- 本机已经安装、且来源声明清晰的 GSAP 技能集；
- 一个开放生态技能发现入口。

首批种子不少于 16 项，与原 4 项演示技能合并后形成约 20 项目录。

## 管线

```text
受控种子清单
  -> 解析 sourceRoot + 相对路径
  -> realpath 边界 / 普通文件 / 大小限制
  -> 安全 YAML 与 SKILL.md 格式检查
  -> 静态安全扫描（block 即隔离）
  -> 许可分类
  -> 仅生成公共目录摘要
  -> 合并 approved listings
  -> 原子生成市场目录与独立详情页
```

## 信任边界

- 不复制 `SKILL.md` 正文，技能真身仍在原技能卷；
- `indexed` 永远是 `source_link_only`、`source_required`；
- 不为批量技能伪造 SMS、Eval、完整包或人工终审；
- 安全阻断、格式失败、路径越界、符号链接和超限文件逐项隔离；
- 公共数据不包含绝对本地路径；
- 在线体验只生成带版本指纹的工作台交接，不在市场浏览器中执行技能。

## 运行方式

```bash
node market-preview/demo.mjs
node market-preview/serve.mjs
```

也可以只生成已收录目录：

```bash
node market-preview/catalog-pipeline.mjs
```

## 验收

- 目录总量达到约 20 项；
- 分类、中文搜索、详情页、创作者、演示价格、在线体验入口均可用；
- 新收录技能显示“已收录，待评估”，不会显示虚假得分；
- 每项都有独立详情路由；
- 重复运行身份稳定，不手工维护生成数据；
- 原市场、可信供应链和 CLI 回归保持通过。
