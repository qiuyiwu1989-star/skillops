# 技能 HRD 方法论（小能对外表达的权威口径）

> 出处：V3 宪法（`~/Documents/skillops/V3-ARCHITECTURE.md`，含七面承重墙决议 + 修正案一至四）。本文是给小能日常引用的浓缩版；与宪法冲突时以宪法为准。

## 一句话

**SkillOps = AI 技能的人事部（HRD）**：技能散在哪都行（file-as-truth），SkillOps 负责它们的全生命周期——就像 HR 管人，从招聘管到退休。今天的 skill 世界 = npm 出现之前的 JavaScript 世界：格式已开放（SKILL.md）、版本已免费（git），缺的是 registry + 信任 + 调度这个中间层。

## HRD 生命周期（核心类比）

| HR 动作 | 技能动作 | 含义 |
|---|---|---|
| 招聘 | 捕获 | 技能在会话中**出生**（一等动词，修正案三）或从外部发现引入 |
| 报到 | **落户** | 给技能登记身份 `id: namespace/name`（写进 frontmatter 一行） |
| 建档 | **入册** | 进入花名册（`skillops scan` 盘点索引） |
| 派岗 | **调度/部署** | 把技能装进对的 agent/项目（P2：deploy + 台账 + 漂移警报） |
| 考核 | **考核** | SMS 静态分（潜力）+ eval 台架实测（实证，P2） |
| 培训 | **培训** | coach 针对弱维提分改写 |
| 入编 | **入编** | 组织收编个人技能：带血缘 `adopted_from`、锁版本、考核门槛、权限、审计（P4） |
| 调薪续聘 | **续聘** | 组织主动把编制升级到新版本 |
| 退休 | **退休** | 生命周期终点，frontmatter 标 `status: retired`，绝不删文件 |

## 五层架构

| 层 | 内容 |
|---|---|
| L0 格式 | SKILL.md 开放标准（不发明私有格式）+ `id`/`version` frontmatter |
| L1 本体 | 卷（vault）+ CLI：盘点/落户/调度 —— **每日动词** |
| L2 信任 | SMS 评分 + eval 台架 + 使用遥测 |
| L3 流通 | registry：发布/订阅/安装；个人免费、组织私有收费 |
| L4 治理 | 组织控制平面：入编/锁版本/门槛/审计 |

## 关键决议（承重墙 + 修正案，全部已批）

- **file-as-truth**：真身是文件夹，DB 永远只是索引。分裂即死亡。
- **操作者条款**（修正案一）：**agent 操作，人拍板**。CEO 不操作 HR 系统——HR 专员操作、向 CEO 汇报。
- **两级命名空间**：个人（`qiuyiwu/`）创作使用，组织（`yongle-edu/`）收编治理——"用户使用，组织管理"。
- **红线（质检台架表述）**：不做生产工作负载的运行时，但做质检台架。eval 是考核不是干活（HR 面试候选人 ≠ 替他上班）。生产执行永远在用户自己的 AI 里。
- **双平面**（修正案四）：本体是系统，agent 是**岗位**不是应用。本地面 = 手（CLI/hooks/本技能）；远程面 = 嘴（远程 MCP link+key → P3 改接托管卷后成为**组织分发轨道**：训练营发一个链接+一把 key，学员任何 AI 30 秒上岗）。key 分级：调用 key（只读）≠ 管理 key。
- **开闭落子**（GitHub 同构）：开——格式、SMS rubric（发表成标准）、CLI；闭——托管信任数据（eval 史/使用数据/信用图谱）、registry 服务、企业控制平面。
- **day-1 可私有化**：不引入 SaaS-only 依赖（中国企业终局必答题）。
- **验收判据 v2**：agent 管理动作 ≥5 次/周 + 户主周报拍板 ≥1 次/周 + 新技能 24h 入册率 100%。不达标回炉，不许绕过。

## 词汇表（署名的语言，表达时保持一致）

**卷**（技能根目录）· **花名册**（索引）· **落户**（登记 id）· **入册**（进花名册）· **分身**（同内容多处拷贝=手工部署）· **分歧**（同身份不同内容=版本漂移，最要命）· **台账**（部署记录 lock.json）· **入编/续聘/退休**（组织治理动词）· **户主**（CEO 邱懿武）· **小能**（专员，本技能）。

## 对外一段话（可直接复用）

> 每个用 AI 的人都在积累技能（提示词、SKILL.md、工作流），但它们散落各处：没有花名册、没有版本、坏了没人知道、好坏没有标准。SkillOps 用人事管理的思路管技能——落户、调度、考核、培训、入编、退休，全生命周期。个人先把自己的技能管起来；组织像发工牌一样发技能包（一个链接+一把 key，员工/学员的任何 AI 立刻上岗）。我们不做运行时——技能永远跑在你自己的 AI 里，我们做的是那个人事部。

## 与永乐理论的同脊（对外讲高度时用）

SkillOps 与创造者教育切的是同一刀：**机器能替你保管的（能力/技能），交出去管理；你必须亲自成为的（意图/判断/拍板），留在人身上。** 修正案一（agent 操作、人拍板）就是"挣扎预算"在产品架构里的投影。
