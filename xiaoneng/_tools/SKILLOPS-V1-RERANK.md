## 0. 定位（锁定）
- **一句话**：你私人的、跨 AI 中立的提示词/技能库 —— 能版本化、越用越好、在任何 AI 里随手调起。（AI 技能的 1Password）
- **ICP**：个人版 = B 知识工作者（讲提示词，不讲 curl）作为 on-ramp；终局 = 团队/企业。
- **引力中心**：中立 / 便携。对手 = ChatGPT Projects / Custom GPT / Claude Projects（锁定、孤岛、搬不走）。
- **身份**：对内按平台造（数据模型预留组织/权限/治理），对外按工具卖。

## ★ 产品脊梁（最重要的一张图）
**运行(引信) → 管理(核心·护城河) → 治理/团队(终局·收入) → 市场(第二幕·网络)**
- **运行**让管理变得**必要**：skill 被调用了，"现在线上哪个版本""它退化了吗"才成真问题。
- **管理**把价值**沉淀**成长期资产与护城河 —— 这是我们能独占、Capafy 够不到的地方。
- **治理/团队**是终局与收入（企业 skill 控制平面）。
- **市场**是第二幕，由前三步引爆，且按 Capafy 教训做对（见 §6）。
> 不是排名，是闭环。评分(SMS)是钩子，不是主张。

## 1. 产品定义
一个本地优先的个人 AI 技能库：把好用的提示词存进来 → 即时评分并迭代成版本 → 在你用的任何 AI 里一键调起 → 像管资产一样管理它的全生命周期。
- **对象模型**：Skill / Version(不可变快照+SMS分+changelog+"当前线上"指针+回滚) / Score / Library(个人,默认私有) / Access(复制/插件/分享链接 + 权限)。
- **核心循环**：捕获 → 提纯 → 调用 → **管理/积累** →(第二幕)共享。留存指标盯**调用次数**，不是创建数。
- **企业唯一接缝（现在就留好）**：`Library.owner` 个人→组织；`Access` 私有/公开→角色/谁能用。今天 db.js 的 `skill.ownerId` + `visibility` 已是雏形，迁移零成本。

## 2. 四象限重排（定位 ↔ 我们手上的真实代码）

### ✅ 保留 + 强化（核心地基）
- **管理中心**（三栏控制台：生命周期 / 版本 / 评分 / 培训 / 发布）—— **这是 centerpiece，是护城河，不藏。** Capafy 完全没有"管"，这正是我们独占的轴。
  - 唯一要做的不是埋掉它，而是**渐进式呈现**：3 个 skill 时界面轻、30 个时火力全开。同一控制台随使用量长出来。
- 个人库 + 本地优先 + 零登录 + 账号 key 同步 —— `dashboard` Local store + `/auth/account`
- 版本 + 回滚 + 分数趋势 —— `platform.js` versions + 控制台「版本」tab
- SMS 100 分制 10 维引擎 —— `scoring.mjs`（保留能力，呈现上降为钩子）
- 数据模型企业接缝 —— `db.js` ownerId / visibility（M1 校验，不重做）

### 🔁 改框（同一个东西，换说法 / 换层级）
- **术语**：skill→技能/提示词 · tier→段位(弱化) · registry→市场(弱化) · **B 主线删 curl**
- **首页矛尖**：评估+市场+API → 「你的提示词库 · 任何 AI 随手调起，还越用越好」（运行打头，评分降钩子）
- **评分**：从"总分头条" → 钩子（"值几分？怎么改？"）
- **/u/ 公开页**：从"市场展示" → "便携/可分享"证据

### 🔽 降权（藏进二级，**降权 ≠ 删除：架构留好，第二幕再点亮**）
- 技能市场搜索 / fork —— `/registry`、`/public/search`、`/app/skills/fork` → 个人版里"轻发现"二级入口；完整形态是第二幕（§6）
- API / curl 一行拉取 —— `/v1/me/skills` → 收进"开发者/高级"区。**注意：开发者当用户(A)这条腿已建好，不杀，只是不在 B 首屏头条。**

### ❌ 新建（让管理"有意义"的引信，目前是空的）
- **调用层**：① 复制即用（一键复制到任何 AI，带格式适配）② 浏览器插件（`/技能名` 注入 + 捕获）—— 分两阶段
- **捕获入口**：从对话"存这段"（插件）；过渡期 = 粘贴进库（已有）
- **调用埋点**：复制/注入计数 → 让管理中心看得见真实使用，驱动留存指标

## 3. 调用度量方案（动手前的工程前提）
没有它就无法验证矛尖、管理也看不见真实使用。
- **web 端**：「复制」按钮触发 `POST /api/track {skillId, action:'copy', ts}` → 每个 skill 累加 `invocationCount` + 轻量时间序列。
- **插件端（阶段二）**：注入事件上报同一端点。
- **呈现**：控制台「概览」显示"被调用 N 次"；右栏分布加"最常调用 Top"。

- **做**：管理中心(渐进式) · 库(捕获/分类/搜索) · 版本+回滚+趋势 · SMS 钩子 · **复制即用 + 埋点** · 分享只读链接(/u/) · 本地优先+账号同步

## 6. 竞品：Capafy（2026-05 上线）+ 第二幕市场怎么做对
**Capafy = Skill-based Agent 市场**：专家把工作流封成 skill，**闭源、服务端执行**（买家只拿输出、看不到 prompt/代码/方法论），按次/订阅付费；粘 install URL 进 Claude Code/Codex/OpenClaw 一键跑。
- **和我们对立两极**：它服务卖家变现 + 靠闭源锁定；我们服务 owner 自用 + 靠中立便携。它**自己当运行时**，我们**明确不当**。
- **它的存在反证我们对**：开源/可 fork 的市场是弱命题（创作者不会把最好的 skill 白给）→ 个人版的"市场搜索/fork"供给注定薄，降权对了。
- **它没有的、我们独占的 = 管理/治理 + SMS 质量信用层。**

**第二幕市场据此做对（不重蹈开源白嫖）**：
1. 不做开源可 fork 市场。走 **(a) 企业内部市场**（公司内 skill 控制平面，按权限调用、不泄漏方法论 —— 跟"个人→企业"终局最顺）或 **(b) 保护/变现**（借 Capafy 的闭源按需调用）。
2. **SMS 当市场信用层** —— 我们能独占、Capafy 没有（它只有"卖"，没有"什么算好"）。
3. 个人版先攒下"真在用、有评分的真 skill + 活跃用户 + 质量标准"，再翻"分享/发布"开关 —— 供给、需求、信任层全是热的（come for the tool, stay for the network）。
