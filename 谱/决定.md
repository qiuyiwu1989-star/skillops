# 拍过的板

> 一条决定三行以内：定了什么 · 为什么 · 什么时候定的。
> **改口不是问题，两边记录打架才是问题**——改了旧的标「已作废」。

## 一、七面承重墙（2026-07-05 · V3 重构逐面裁决）

**D01 · 真身放哪：file-as-truth**
技能真身 = 用户各处的 SKILL.md 文件夹（卷），数据库永远只是索引/缓存。
为什么：DB-row-as-truth 会制造第二份拷贝，用户心里知道真身在文件里 → 分裂即死亡。

**D02 · 先赢谁：A 优先 + 自有场景当种子**
Wedge 从 B（ChatGPT 网页知识工作者）改判为 A（agent-native builder）；种子 = 自己 → builder 圈 → 训练营。
为什么：B 没咬钩，而主人这个标准 A 用户也绕开了产品；训练营本身就是微型组织 = 治理层试验田。

**D03 · 技能身份：两级命名空间「用户使用，组织管理」**
`id: namespace/name` 写进 frontmatter；个人 `alice/` 创作，组织 `acme/` 收编（入编带血缘 + 锁版本 + 门槛 + 审计）。
为什么：没有身份体系，registry / 血缘 / 漂移检测全是沙上塔。

**D04 · 红线重述：质检台架**
"不做生产工作负载的运行时，但做质检台架"——eval 是考核不是干活（HR 面试 ≠ 替他上班）。
为什么：eval 要真跑 agent，必须说清它不违反"不当运行时"。

**D05 · eval 算力：v0 自带**
用用户自己的 LLM 订阅在本地跑，golden cases 由技能作者写。registry 时代才上官方算力跑公开榜。

**D06 · 开闭落子：GitHub 同构**
开：格式跟随 SKILL.md、**SMS rubric 公开发表**、CLI 开源。闭：托管的信任数据（eval 历史/使用数据/信用图谱）、registry 服务、企业控制平面。
为什么：认知护城河要输出才能成标准；数据与网络才是闭合处。

**D07 · 架构约束：day-1 可私有化**
所有决策不引入 SaaS-only 依赖（零依赖 Node + 自托管 Supabase 已验证）。商业上先只卖托管版。
为什么：中国企业终局几乎必然要求私有化部署。

## 二、四条修正案（2026-07-19 · P1 验收不达标后回炉）

**D08 · 修正案一：操作者条款**
操作者 = 用户会话里的 agent；人 = 拍板者。CLI 重新定位为 agent 的手。
为什么：主人 14 天 0 次亲手使用（连验收命令都没跑）——他的一切界面是对话。**把操作台发给 CEO 是设计错误。**

**D09 · 修正案二：验收判据 v2**
① agent 经 skillops 完成的管理动作 ≥5 次/周 ② 主人每周 ≥1 次读周报并拍板 ③ 新技能出生 24h 内入册率 100%。
旧判据（主人每周亲手用 ≥3 次）**已作废**——那是测量错误，混淆了 CEO 和专员的 KPI。

**D10 · 修正案三：捕获一等动词**
技能在会话中出生 = 招聘现场，出生即入册+落户，agent 顺手完成不打断工作流。
证据：主人技能出生率 3 个/14 天，是最高频的管理时机。

**D11 · 修正案四：双平面**
本体是系统（确定性/可审计），**agent 是岗位不是应用**——寄生于用户已有的各家 AI，不自建聊天应用。
本地面=手（CLI+hooks+技能，P1.5）；远程面=嘴（MCP link+key，P3 改接后升格为**训练营组织分发轨道**）。key 分调用/管理两档。

## 三、其他拍板

**D12 · 独立建仓 + 私有**（2026-07-20）
SkillOps 从 qiuyiwu.com 网站仓库抽出 → `~/Documents/skillops/` 独立仓库，GitHub **私有**。
原想公开，发现混着基建泄露面（服务器 IP、私有域名、绕 ICP 墙手法、评分引擎护城河）→ 改私有。要开源须先脱敏。

**D13 · 便携标准包对外可分发**（2026-07-29）
方法论做成零硬编码的独立技能包（`dist-src/skillops/`），任何第三方 agent 解压即用；SMS 标准与方法论**公开发表**，署名造物云 · 邱懿武。

**D14 · 老平台冻结**
`api-server/`、`xiaoneng/`、线上 skillops.tech 在 P3 改造前一行不动；新代码只长新目录，新旧并行。

**D15 · V3.1 聚焦技能的一核两面**（2026-08-12）
造物云能力市场可承载插件、方法、应用、数字员工等形态；SkillOps 本版只管技能。对外提供可信技能供给，对内管理技能身份、版本、部署与提升。

**D16 · 抓取只进候选池，人工准入**（2026-08-12）
公开来源的 `SKILL.md` 必须经过来源、许可、安全硬门和质量评估；候选永不自动上架，安全/许可硬门不能被 SMS 综合分抵消。许可证不明确只索引源链接。

**D17 · 版本身份绑定内容与许可**（2026-08-12）
批准只对审核时的内容指纹与许可成立；正文或许可证变化，原批准自动失效并进入 `stale`。市场卡生成时重新计算正文指纹，防止存储篡改绕过审核。

## 四、明确不做

- ❌ 自建 AI 执行运行时（不跑推理）
- ❌ 提示词社交网络 / 排行榜虚荣场
- ❌ 开源可 fork 的技能市场（Capafy 反证了这是弱命题）
- ❌ 自建聊天 App / 让用户来"访问"的目的地（会重蹈 dashboard 覆辙）
